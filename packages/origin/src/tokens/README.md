# Token role guide

How to choose surface, border, and alpha tokens.

`_variables.scss` is generated from the token JSON in `tokens/figma/`; edit
the JSON and run `yarn tokens:build`. `_text-styles.scss`, `_typography.scss`,
and `_effects.scss` are generated by the style sync workflow. Do not edit these
generated files directly. The other SCSS files in this directory are
hand-maintained. In particular, `_dark-effects.scss` is the source of truth for
theme-specific effect overrides that must remain separate from generated
effects.

The JSON is the source of truth for color, spacing, and sizing tokens. Keep
design variables and repository tokens in sync through deliberate, reviewed
updates.

## Surfaces

The rank axis (`--surface-primary`, `--surface-secondary`, `--surface-tertiary`)
is legacy. Prefer the context axis below in new code. Existing app shells keep
`--surface-secondary` as their validated floor: it is `--color-gray-100` in
light and matches the page/base floor (`--color-gray-990`) in dark. Do not add
a parallel `--surface-shell` role; the existing secondary consumers rely on
this mapping.

| Token                      | Role                                                                                                  |
| -------------------------- | ----------------------------------------------------------------------------------------------------- |
| `--surface-base`           | Root floor of the app — the lowest layer everything sits on                                           |
| `--surface-page`           | Page canvas — the main content background one step above base                                         |
| `--surface-primary`        | Cards and in-page containers                                                                          |
| `--surface-panel`          | Raised floating panels whose light treatment predates the contextual surface roles                    |
| `--surface-overlay`        | Popup surfaces that used the page-level surface in light mode before contextual roles were introduced |
| `--surface-raised`         | Floating fill one notch above the panel it sits on                                                    |
| `--surface-control`        | Input chrome (text fields, selects)                                                                   |
| `--surface-track`          | Rails and tracks (sliders, switches, progress)                                                        |
| `--surface-handle`         | Thumbs that ride on tracks                                                                            |
| `--surface-neutral-subtle` | Quiet neutral furniture and chrome                                                                    |
| `--surface-*-strong`       | Solid chromatic fills paired with theme-invariant on-color text or icons                              |
| `--surface-neutral`        | Strong neutral fill                                                                                   |
| `--surface-backdrop`       | Dimming layer behind modals                                                                           |

## Borders

Border tokens split by role, not by strength. Affordance edges — strokes on
interactive controls the user is invited to act on (inputs, select triggers,
outline buttons, pager chrome, selected-segment keylines) — use
`--border-control`. Containment edges — hairlines that separate or frame
content (table rules, card outlines, panel dividers, cap dividers inside
input groups) — use `--border-primary`, `--border-overlay`, or
`--border-keyline`. In light the two roles happen to share a value; in dark
affordance edges read stronger than containment on purpose.

| Token              | Role                                                                                             |
| ------------------ | ------------------------------------------------------------------------------------------------ |
| `--border-primary` | In-page containment hairlines (tables, cards, dividers)                                          |
| `--border-overlay` | Containment hairlines on floating panels, menus, dialogs                                         |
| `--border-keyline` | Transparent in light by design; separates panels in dark where shadow alone did the job in light |
| `--border-control` | Affordance edges: outline-control strokes (inputs, checkboxes, outline buttons)                  |

## On-color text and icons

`--text-on-color` and `--icon-on-color` are theme-invariant: they keep the same
value over chromatic fills (buttons, badges) in both themes. Never substitute
`--text-inverse`, which flips with the theme.

## Alpha temperature

Translucent neutrals follow the theme's temperature: light mode uses the
`alpha/temp-black` ramp, dark mode uses `alpha/temp-white`. The one deliberate
exception is `--surface-backdrop`, which stays true black in dark. Do not add
new true-white or true-black alpha consumers without a doctrine reason.
